# ADR 0001: Content Security Policy through Astro's `security.csp`, with Prism

- **Status:** accepted, 25-09-26. Deny by default after the S1 security review.
- **Measured on:** astro 7.3.5, @astrojs/mdx 8.0.2, @astrojs/react 7.0.0, Node 22.22.3, Chromium 153
  (Playwright 1.63.0).
- **Config:** `astro.config.mjs`.

## Context

The plan requires Astro's generated CSP hashes with no `unsafe-inline` or `unsafe-eval`, and Prism rather
than Shiki, with both claims checked on the installed version. Astro's own docs for `security.csp`
(`astro/dist/types/public/config.d.ts`) say that Shiki is not supported, that `<ClientRouter />` is not
supported, and that the policy is not applied in `astro dev`.

## Method

Throwaway worktrees, built with `astro build` and served with `astro preview --ignore-lock --host 127.0.0.1`.
A short Playwright script recorded every `securitypolicyviolation` event (through `addInitScript`) and
every console error. Experiments a to g ran on `efb1ef9` (`default-src 'self'`); a, d and g ran again on
`39a5e0f`, the committed deny-by-default policy. f and g were added to the plan's five to measure the
limits below instead of deriving them. Both worktrees were deleted.

## Decision

- `security.csp` with `default-src 'none'`, `img-src 'self'`, `base-uri 'none'` and `form-action 'none'`;
  Astro adds `script-src` and `style-src` with its hashes. `object-src` and `frame-src` fall back to
  `'none'`. Each later need is one reviewed line: `font-src 'self'` for self-hosted fonts (added in Phase 5),
  `connect-src 'self'` only in analytics builds (D11; Pagefind needs none, F6), `worker-src 'self'` for a worker,
  `media-src 'self'` for Emma's audio files (added 28-09-26).
- Highlight code with Prism (`markdown.syntaxHighlight: 'prism'`), which ships inside Astro 7's default
  Markdown processor, so it costs no dependency. Prism emits classes, so a token theme is plain CSS.
- Every browser gate runs on `astro build` output, never on `astro dev`, where the policy is not applied.

## Limits and consequences

- **A `<meta>` policy ignores `frame-ancestors`, `sandbox` and `report-uri`** (Chromium logs an error for
  each, which fails the smoke test), and `report-to` needs a `Reporting-Endpoints` header.
- **The deploy header is enforced together with the meta.** A header carrying `default-src`, `script-src`
  or `style-src` without Astro's hashes blocks the islands. The header adds only what a meta cannot:
  `frame-ancestors 'none'` (plus `X-Frame-Options: DENY`), `X-Content-Type-Options: nosniff`,
  `Strict-Transport-Security`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`,
  a `Permissions-Policy` that turns off unused features, and `default-src 'none'; sandbox` for files
  served from `public/`, which get no meta (dropped by ADR 0003: `public/` holds nothing that runs).
  No report endpoint: a report is a request off the device. Written fresh; NBEDU's `vercel.json` is never copied.
- **Astro writes the meta at the start of its own head block, after the layout's tags.** An `is:inline`
  script or `<style>` in `Base.astro`'s `<head>` runs outside the policy (measured by S1).
- **Astro 7.3.5 hashes no `is:inline` script, in the head or the body** (Phase 5, F4): Chromium logs
  "Executing inline script violates ... script-src-elem" and the script sets nothing. So the
  theme-before-paint script, `src/boot.js`, is the first child of `<body>`, rendered with `set:html` from a
  `?raw` import, and `astro.config.mjs` adds the `sha256-` of the same file through
  `security.csp.scriptDirective.hashes` (F5): an edit can never leave the page and the policy out of step.
- **Astro checks directives by prefix only**, so a `;` inside one entry smuggles a second directive.
  Chromium keeps the first and logs "Ignoring duplicate", which the smoke test's console check catches.
- **`<ClientRouter />` is unsupported.** Use the browser's native View Transition API if needed.
- **Server-rendered `style` attributes are blocked, and hydration does not fix them (g).** Islands style
  with classes, or write through the CSSOM after mount; `motion` animates through the CSSOM.
- **`data:` images are blocked (g).** Vite inlines assets under 4 KB as `data:` URIs, so Phase 4 sets
  `vite.build.assetsInlineLimit: 0`. The key `build.assetsInlineLimit` is silently ignored.
- **`astro preview` backgrounds itself when it detects an agent** (Astro 7's `am-i-vibing` check), so
  scripts that must own the server pass `--ignore-lock`, which keeps it in the foreground.
